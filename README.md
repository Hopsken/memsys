# memsys

A tiny associative memory system for agents.

Cloudflare Workers project setup. No application routes, tables, or features are defined.

## Toolchain

- Node.js 24 and pnpm 11, pinned through Mise.
- Hono for HTTP routing; TypeBox and `@hono/typebox-validator` for future request validation.
- Cloudflare Durable Objects with SQLite storage, Drizzle ORM, and Drizzle Kit.
- Strict TypeScript with binding types generated by Wrangler.
- Vitest with the Cloudflare Workers pool for tests in the Workers runtime.
- Oxlint and Oxfmt with Ultracite presets.

This is one Worker package. Add workspaces and Turbo only when there are more packages to manage. Add other Cloudflare resources, such as R2, KV, or Queues, when a feature needs them.

## Local development

```sh
mise install
pnpm install --frozen-lockfile
pnpm typegen
pnpm dev
```

Wrangler runs the Worker and SQLite Durable Objects locally. No Cloudflare account is needed for local checks. The Worker returns Hono's default 404 response until routes are added.

```sh
pnpm check        # Generate types, typecheck, test, dry-run build, lint, format check
pnpm format       # Format source and configuration
pnpm lint:fix     # Apply lint fixes
```

The generated `worker-configuration.d.ts` is ignored. Run `pnpm typegen` after binding changes. Keep local secrets in the ignored `.dev.vars` file.

## Database

`MemoryDO` owns a Drizzle database backed by its own SQLite storage. The `MEMORY` binding is a Durable Object namespace, not a shared database. Future routes can select an object with `env.MEMORY.getByName(name)`; each identity has separate storage. No business RPC methods or object naming policy are defined yet.

`src/db/schema.ts` is empty. When tables are needed, define them with `drizzle-orm/sqlite-core`, then generate migrations:

```sh
pnpm db:generate descriptive-migration-name
```

Drizzle Kit uses `driver: "durable-sqlite"`. Commit the generated SQL, snapshots, and `migrations/migrations.js` bundle with its declaration file. Wrangler imports SQL as text and includes it in the Worker bundle.

Each object runs bundled migrations inside `blockConcurrencyWhile` during initialization, before it accepts requests. There is no separate local or remote SQL migration command. The bootstrap migration bundle is empty; initialization only creates Drizzle's migration bookkeeping table, not business tables.

Wrangler's `migrations` setting has a different role: `v1` registers `MemoryDO` as a SQLite-backed class through `new_sqlite_classes`. Future class changes need new Wrangler migration tags; table changes use Drizzle migrations.

## Deployment

No remote resources have been created. No D1 database or database ID is needed. After review:

```sh
pnpm deploy
```

Deployment requires Cloudflare access, publishes the Worker, and registers the Durable Object class. SQL migrations run when each object initializes with the deployed code, not on all objects at deployment time. `pnpm build` only creates a local dry-run bundle.
